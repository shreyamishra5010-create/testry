# RCA — task-board-305 deploy failure (run 1e8b1b8d-e7ef-4415-bd8d-ca23a4684383)

## Symptom
`deploy_k8s` fails: "deployment failed to become ready: timeout waiting for deployment to be ready". Pods never become ready; the backend crashes on boot and nginx is shut down, repeatedly. Same failure on the prior run (e8ee78a2...).

## Root cause (proven)
The app backend is a **Node.js / Express** API, but it is being deployed with the **FARM Python template** (`fastapi_react_mongo_shadcn_base_image`) whose runtime image contains **no `node` binary and no backend `node_modules`**.

Evidence from the run source (inspected in an eph sandbox):
- `backend/server.py` (line 20, the lifespan) is only a launcher/proxy:
  ```python
  proc = subprocess.Popen(["node", "server.js"], cwd=ROOT, env=os.environ.copy())
  ```
- `backend/server.js` is the real API — an Express app (`express`, `cors`, `jsonwebtoken`, `bcryptjs`) backed by **SQLite** (`backend/taskboard.sqlite`, `schema.sql`, `seed.sql`, dep `sqlite3`). `package.json` declares these Node deps.
- The runtime/build path is Python-only. In `Dockerfile` / `Dockerfile.cloudbuild` the final image is `FROM ${BACKEND_IMAGE}` (python:3.11 base) and the build **only** runs `pip install -r backend/requirements.txt`. There is **no `node` runtime installed and no `npm/yarn install` for backend node_modules** anywhere in the backend/final stages.

At boot the FastAPI launcher tries to spawn `node server.js`, the binary is absent, and it raises:
```
FileNotFoundError: [Errno 2] No such file or directory: 'node'
  File "/app/backend/server.py", line 21, in lifespan
    proc = subprocess.Popen(["node", "server.js"], ...)
ERROR:    Application startup failed. Exiting.
```
With the backend dead, `entrypoint.sh` logs "Backend died, shutting down nginx...", so `:8080` stops serving, the k8s readiness/startup probe on `/health` gets connection-refused, and the rollout times out. This is why `deploy_k8s` never goes green.

## Why this is NOT a manifest fix
Making this run would require fundamentally changing the template: adding a Node runtime to the Python base image AND building native node_modules (`sqlite3`/`bcryptjs` need a compile toolchain) in the build — a speculative, large rewrite that converts the stock FARM template into a dual-runtime image. On top of that the app persists data in a **local SQLite file**, which does not survive pod restarts and is not shared across replicas, and it ignores the platform-provisioned MongoDB (`MONGO_URL`). This is an application-architecture problem, not a deployment-manifest defect. No secret, tier, or infra change addresses it.

## Recommended fix (Code / E1)
Rewrite the backend to the template's native stack so no `node` subprocess is needed:
1. Replace the Node/Express API (`server.js`, `src/*.js`, `package.json`) and the `server.py` launcher/proxy with a **native Python FastAPI** app in `backend/server.py` exposing the same `/api/*` routes (health, auth, boards, columns, tasks, comments), served directly by uvicorn.
2. Replace **SQLite** persistence with **MongoDB** via the platform-provided `MONGO_URL` / `DB_NAME` (motor/pymongo) so data persists and works across replicas. Migrate the schema/seed logic (`schema.sql`, `seed.sql`) to Mongo collections.
3. Remove `backend/server.js`, `backend/src/*.js`, `backend/package.json`, `backend/*.sqlite`, and the `subprocess.Popen(["node", ...])` launcher. Keep `backend/requirements.txt` as the single dependency source.

After the rewrite, redeploy. (No manifest override was written; pipeline not re-fired.)
