# RCA — run e8ee78a2-716f-4359-a8f4-9437272ef52c (task-board-305)

## Symptom
Deploy failed at the `deploy_k8s` step: "deployment failed to become ready: timed out waiting for the condition." The backend container crash-loops on boot, nginx then exits (`Backend died, shutting down nginx...`), and `/health` returns connection-refused.

## Root cause (PROVEN)
The backend crashes at startup with:
```
FileNotFoundError: [Errno 2] No such file or directory: 'node'
  File "/app/backend/server.py", line 21, in lifespan
    proc = subprocess.Popen(["node", "server.js"], cwd=ROOT, env=os.environ.copy())
```

The app's `backend/server.py` is only a thin FastAPI launcher/proxy. On startup it tries to spawn a **Node/Express** API (`node server.js`) and reverse-proxies all requests to it. The real backend is a Node app:
- `backend/server.js` — Express app (`express`, `cors`, `jsonwebtoken`, `bcryptjs`).
- `backend/src/db.js` — persistence via **SQLite** (`sqlite3`, file `backend/taskboard.sqlite`, loads `schema.sql`/`seed.sql`).
- `backend/package.json` → `"start": "node server.js"`.

This does not fit the deployment template for this app: `fastapi_react_mongo_shadcn_base_image` (FARM). The production runtime image is **Python-only** — it has no `node` binary and no backend `node_modules`. So `subprocess.Popen(["node", ...])` throws `FileNotFoundError`, the ASGI lifespan fails, uvicorn exits, the pod never becomes ready, and the rollout times out.

Verified in an eph sandbox from this run's source:
- `backend/node_modules` is absent (never installed by the build).
- Backend data layer is SQLite only — `grep` found no Mongo usage anywhere in `backend/src`. The platform-provisioned `MONGO_URL` is ignored.

## Why this is NOT a manifest/infra fix
Papering over it by adding Node + `npm install` (incl. native `sqlite3` build) to the runtime Dockerfile would be fighting the template and would still leave a second, worse problem: **the app stores all data in an ephemeral SQLite file inside the container** (`backend/taskboard.sqlite`). That file is wiped on every pod restart/redeploy and is not shared across replicas — unacceptable for production, and it bypasses the provisioned MongoDB entirely. The correct fix is in the source, not the manifests.

## Required fix (Code — E1 / main agent)
Rewrite the backend to the FARM template's intended stack so it matches the Python/Mongo runtime:
1. Reimplement the Express routes (`src/routes/{auth,boards,columns,tasks,comments}.js`, `src/auth.js`, `src/access.js`) as a native **FastAPI** app in `backend/server.py`, mounted under `/api`, with a `/health` (or `/api/health`) route.
2. Replace the SQLite layer (`src/db.js`, `taskboard.sqlite`, `schema.sql`, `seed.sql`) with **MongoDB via `motor`**, using the platform `MONGO_URL` / `DB_NAME` env vars (these are injected by the platform at deploy time).
3. Remove the `node server.js` subprocess launcher and the Node proxy entirely; delete `backend/server.js`, `backend/src/*.js`, `backend/package.json`, `backend/yarn.lock`. The entrypoint runs `uvicorn server:app` directly — no Node process should be spawned.
4. Keep `requirements.txt` as the only backend dependency manifest.

After E1 rewrites the backend to Python/FastAPI/Mongo, trigger a fresh deploy.
